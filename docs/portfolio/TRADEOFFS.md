# Tradeoffs

**Pseudonymous audit logs:** Domain-separated HMAC user/client references preserve correlation while excluding raw user IDs, IP addresses and arbitrary browser metadata from exported logs. They are still sensitive pseudonyms. Rotating the server key intentionally breaks historical joins, and omission of user-agent detail reduces browser-specific incident diagnostics. Existing operational session/login-attempt database records are a separate retention boundary.

**Editorial discovery:** Homepage shelves interleave active image-backed database products. The shelf named trending is editorial selection, not a sales analytics claim. Personalized ranking remains a separate decision.

**Configuration as SKU:** Variants are independent product records, so price, stock and checkout work without another cart option model. The sibling selector relies on the seed's name prefix; explicit product-family IDs would better support arbitrary authored names.

**Modular monolith:** Shared services keep commerce rules consistent across browser and assistant. Independent service deployment is deferred until operational need justifies it.

**Deterministic commerce routing:** Predictable validation and offline demonstrations are valuable. Language coverage is narrower than unrestricted LLM tool planning; unsupported phrases should receive helpful guidance.

**Stable knowledge RAG:** Policies and guides can use citations. Inventory and discounts must remain live service queries because retrieval can be stale.

**One best promotion:** The current engine avoids unexpected stacking and gives stable tie-breaking. Supporting stackable offers would require explicit combination rules and new tests.

**Order snapshots:** Captured name, SKU, image, unit price and promotions keep history stable after catalog edits. Snapshot storage duplicates some product metadata deliberately.

**Fictional catalog and generated family imagery:** Deterministic source-owned portfolio data supports repeatable demos. Photo-style generated imagery improves presentation but is illustrative family art, not verified manufacturer photography or an exact view of each fictional SKU; several configuration listings intentionally share a family image.

**Lightweight motion:** Transform/opacity animation avoids a large animation dependency. Reduced motion must have a complete static composition. Smoothness, contrast and responsive layout still require browser review.

**Portfolio checkout:** Address and order persistence demonstrate commerce consistency. Payment authorization, tax, fulfillment and refunds are outside the implemented payment scope.

Prefer one concrete limitation plus its measured next step in an interview over claiming the application has every production capability.
